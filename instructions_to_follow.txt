## Instructions followed for image QA + fixing

### A. Per-image quality criteria
1. **Tight crop** — bbox just hugs the diagram; no oversized canvas.
2. **No unnecessary blank space** — if >~30% of the canvas is white background, the bbox is wrong.
3. **No cut-through** — no half-letters or partial axis labels at any edge. Always include descender room (e.g. `t`, `g`, `0`).
4. **Diagram only, no prose** — exclude question stem ("8 A ball is thrown…") and follow-up question text. Include diagram-internal labels (e.g. `F`, `30°`, `crane arm`, `pivot`).
5. **Diagram-related captions are part of the diagram** — captions like "before collision" / "after collision" MUST be inside the crop. Apply uniformly across all sub-figures of the same question.
6. **Option labels inside crop** — for `qNNN_option_X.png`, the letter `A`/`B`/`C`/`D` that sits above the figure must be inside the bbox.
7. **Edge case — labels-on-one-diagram** — when A/B/C/D are point-labels on a single diagram (not separate figures), each `option_X.png` should contain the full diagram (not a slice), and a separate `question_diagram_01.png` should also exist.

### B. Processing constraints
- **One image per Read tool call.** Never load multiple images in a single tool call.
- **Hard ceiling 1800 px on the longer side** for any image fed to the Read tool. Anything taller (e.g. 200 DPI A4 page = 2339 px) must be downscaled first.
- **Page renders for ground truth** — resize 1653×2339 page PNGs to max-1700 (→ 1201×1700) before reading. Keep the originals untouched; resized copies live outside the paper folder (`C:\Temp\…`).

### C. Fix workflow
1. Verify against the resized page render — never against questions.json or layout/.
2. Locate the offending region by **inspect-cropping** the original 200 DPI page PNG (in `pages/`) with PowerShell + System.Drawing, save to `C:\Temp`, Read it, eyeball pixel coordinates.
3. Compute new pixel bbox; crop with `Bitmap.Clone(Rectangle, PixelFormat)`; save to `images_fix/`.
4. Read the result; if any edge is still tight, re-extend ~30 px and re-save.
5. **Filename parity** — produce a fixed file at every existing filename in `images/` that had an issue, so a folder-swap works without leaving stale broken originals. Don't unilaterally drop filenames; flag schema concerns separately in the log.

### D. Logging
- Single file: `claude_log.txt` inside the paper's output folder.
- Per-image line format: `<file> <STATUS> [WxH] <comment>` where STATUS ∈ `OK | NOTE | ISSUE`.
- Tag issues by category: `[crop]` `[blank]` `[cut]` `[text]` `[label]`.
- End the log with a Summary (counts + recurring root-cause patterns) and a Fixes section listing each new file in `images_fix/` with what changed.

### E. What NOT to look at
- Only PDF (in `input/`) and `images/` are the source of truth for QA.
- The `pages/` folder is allowed as a working aid (regenerated by `extract.py`); resize before use.
- `questions.json`, `layout/` are reference only — don't trust them as ground truth for whether a crop is correct.

These rules together produced the 17-file fix in `images_fix/` for `9702_m16_qp_12`(folder as an example).
